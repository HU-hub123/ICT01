## 1. 产品：认知脚手架（thinkingmodels.site）

### 1.1 官网定位与功能全景（来源：[产品官网](https://thinkingmodels.site/)）

定位：**认知助手 × 可溯源思维模型知识库** —— "从一个问题，搭起你的思考结构。"

- **认知助手（三阶段）**：
  1. 外化：把问题摆出来（文字/语音，补充条件、约束、背景）；
  2. 搭建：建立判断依据（参考模型打开角度，**区分事实与假设**，看清选项、关系、后果）；
  3. 迭代：带着新信息继续（追问、决策图、检查原有判断与下一步验证动作）。
- **模型知识库**：围绕当前问题搜索模型；查看定义、实践建议和**信源**；支持分类、模型详情、谱系关系、信源查询。
- **关系与可视化**：模型对照、知识图谱、决策图。
- **学习与决策沉淀**：对话历史、学习路径、**认知账本**、决策工作坊。
- **MCP（5 个公开只读工具）**：get_taxonomy / search_models / get_model / get_model_lineage / get_model_sources。
- **Skill**：三个任务包（问题拆解、决策与验证、学习与复盘），可下载到 Codex / Claude Code。
- 官网声明："**示例用于说明分析过程，不承诺决策结果**"（可视作产品侧对"无依据数字"批评的回应）。

### 1.3 用户提供的差评要点提炼（绿青蛙，约 1 个月前）

1. **追问上下文 bug**：追问时系统只喂用户输入，不含自己上一轮回答，容易判断失误。
2. **多模型没有"交叉推演"**：检索到的模型在共同完成同一论证（如沉没成本+实物期权+终止标准），没有冲突/张力；应主动引入张力模型（路径依赖、学习曲线、贝叶斯更新）让模型"打架"，并问"新证据多大程度改变原判断"。
3. **具体数字无依据**："8–12 周""留存 30% 以上""20 个付费用户"等数字没有数据支撑；模型包装让幻觉数字获得"认知形式感"的额外可信度。
4. **需要五层区分**：用户已提供的事实 / 系统基于模型的推断 / 目前缺失的信息 / 未验证的假设 / 仅为说明方法的示例数字（非推荐阈值）。
5. **"一万个模型"无意义**：大量概念高度重叠；关键不是数量，而是模型之间的结构与**认知操作类型**（发现问题 / 生成解释 / 验证假设 / 判断概率 / 比较选择 / 检查偏差 / 分析动态系统）。
6. **Scaffold Role**：不只说"这是沉没成本"，要明确告诉用户这个模型要求他**执行什么思考动作**（"把不可追回的投入先拿掉，再重新比较从今天起的未来收益"）。
7. **"保存思考结构"未落地**：现在像 Chat History + Learning Tracker；真认知账本应存：当时的问题 / 已确认事实 / 关键假设 / 支持与反对的证据 / 为什么这么决定 / 预期 8 周后看到什么 / 停止条件 / 实际发生了什么 / 哪个判断被推翻。
8. **定位之问**：帮助 AI 答得更好（reasoning RAG）vs 帮助人思考得更好 —— 差评作者认为后者才是价值所在。
9. **长期价值**：半年后能回看"我当时为什么相信 / 哪个假设被现实推翻 / 我常在哪类问题上判断错误 / 什么新证据最容易改变我的判断 / 我是否反复因某偏差做选择"。

## 3. 结论：差评指出的三个可被我们做成硬功能的缺口

1. **真·交叉推演**：模型间张力/冲突显式化 + 证据检查点 + 收敛条件（防死循环）；
2. **五层标注**：事实 / 推断 / 假设 / 缺失信息 / 示例数字；
3. **认知账本**：存判断过程（问题→事实→假设→证据→理由→预测→停止条件→实际结果→推翻记录→长期轨迹）。

对照官网功能清单，原产品已声称有"认知账本""区分事实与假设""示例不承诺决策结果"等要素，说明差评方向已被承认有价值；真正稀缺的是把这三件事做成**硬功能**（而不是检索问答的附加层）。这就是我们作品的差异化位置。
