# PRD 草案 v0.1 · 需求对齐

> 状态：草案，待与用户逐条确认后冻结为 v0.2 开发依据。
> 目标赛事：第十一届华为 ICT 大赛创新赛 · 赛题一（基于华为云产品打造 AI 创新应用）。

## 1. 定位（一句话）

**认知脚手架：让 AI 的思考过程被看见、被检查、被记住、被复盘 —— 拒绝黑盒。**

原产品那句"我们保存了大量结论，却很少保存自己是如何得到这些结论的"就是本作品的锚点。本作品保存的正是"如何得到结论"的全过程：

- 用户提出一个需要判断的问题，AI 通过多个思维模型的交叉推演得出结论；
- 但**结论只是副产品**，真正交付的是可溯源的思考轨迹：为什么选了这些模型（检索依据）→ 每个模型独立怎么推（含成立条件与失效边界）→ 模型之间在哪里冲突 → 什么证据会改变结论 → 每一步的事实/推断/假设成色标注 → 全过程存入认知账本，可随时回看"当时 AI 是怎么得出这个答案的"。
- 一句话（用户明确的核心定位）：**帮助人了解和记忆回顾 AI 怎么输出这个答案，避免黑盒。**

## 2. 硬差异（直接回应差评，全部服务于"防黑盒"核心）

| # | 差异点 | 说明 |
| --- | --- | --- |
| A | **真·张力交叉验证** | 检索模型时强制包含至少一对结论可能冲突的"张力模型"；每个模型独立给出结论 + 适用条件 + 失效边界；冲突点显式列出；给出"什么新证据会改变结论"（贝叶斯式证据检查点）；有收敛/终止条件，防死循环。 |
| B | **五层标注** | 所有输出语句强制打标签：`[事实]`（用户已提供）/ `[推断]`（基于模型）/ `[假设]`（未验证）/ `[缺失信息]` / `[示例数字]`（仅为说明方法，非推荐阈值）。默认不产出来路不明的具体数字。 |
| C | **认知账本** | 保存"判断过程"而非聊天记录：当时问题 → 已确认事实 → 关键假设 → 支持/反对证据 → 决策理由 → 预期结果与观察窗口 → 停止条件 → 实际结果 → 被推翻的假设 → 长期轨迹（常犯偏差统计）。 |
| D | **溯源回放** | 每条回答可展开"AI 怎么得出这个答案"的完整轨迹：模型检索依据 → 各模型独立推理 → 冲突点 → 证据检查点 → 原始结构化输出存档；账本详情页支持逐步回放与对照。 |

## 3. 核心用户旅程（一个完整闭环）

1. **提出问题**（追问时上下文必须包含系统上一轮自己的回答 —— 修复差评中的 bug）
2. **事实收口**（自动列出：已确认事实 / 缺失信息清单；可补充，不阻塞）
3. **模型匹配**（2–4 个模型；至少一对张力模型；每个模型标注认知操作角色 + "要求你执行的动作"）
4. **交叉推演**（各模型独立结论与适用条件 → 冲突点 → 证据检查点 → 收敛判定）
5. **五层标注结论**（结构化输出，数字默认示例）
6. **最小行动**（下一步动作 + 停止条件 + 观察窗口预期）
7. **存入认知账本**（判断过程快照）
8. **复盘**（实际 vs 预测 → 推翻/确认假设 → 长期轨迹统计）

## 4. 技术方案（对齐赛题一）

- **应用形态**：Next.js 全栈（TypeScript + Tailwind），单仓库前后端一体，Node LTS。码道 CodeArts 流水线可直接构建，Docker 单镜像部署华为云。
- **存储适配层**：默认本地 SQLite（开发/演示零依赖）↔ 生产切华为云 **RDS**（MySQL/PostgreSQL）+ **Redis**（会话/缓存/限流）。全部走 env 配置与适配器接口，对应赛题"关联 RDS、Redis 等华为云服务快速开通创建"。
- **AI 适配层（Provider 接口，可插拔）**：
  1. `deepseek`（**当前主引擎**）：直接接 DeepSeek API（OpenAI 兼容），真实模型推理，**不伪造模型效果**；用结构化 JSON 输出驱动张力推演与五层标注；
  2. `openai-compatible`（通用）：同一接口可换华为云 ModelArts 推理端点或其他兼容服务（只换 BASE_URL + KEY）；
  3. `codearts`（预留）：接码道 CodeArts 代码智能体与 Skills；
  4. 网络/密钥异常时给出明确错误提示与重试指引，**不做"看起来像 AI"的假输出**。
- **交付与开源**：git 仓库 + README / LICENSE / .gitignore + GitHub Actions CI + Dockerfile + docker-compose + 部署说明；满足赛题"开源至 Gitee/GitHub"要求。
- **反幻觉与防死循环机制**：
  - 模型库条目强制带：认知操作角色 / 适用条件 / 失效边界 / 谱系关系 / 信源；
  - 输出强制五层标签；一切具体数字默认 `[示例数字]`，除非来自用户提供的事实；
  - 交叉推演终止条件：冲突点已标注 + 证据检查点已列出即收敛；单轮推演最多 2 轮；
  - 账本预测必须含观察窗口与可证伪的停止条件。
