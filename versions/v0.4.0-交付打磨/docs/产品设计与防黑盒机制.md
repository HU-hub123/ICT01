# 产品设计与防黑盒机制

> 本文件说明「认知脚手架 · 可溯源思考工作台」的产品设计逻辑，
> 以及它如何逐条回应真实用户差评与"拒绝黑盒"的核心定位。

## 1. 一句话定位

**让 AI 的思考过程被看见、被检查、被记住、被复盘 —— 拒绝黑盒。**

原产品介绍里那句话是本作品的锚点："我们保存了大量结论，却很少保存自己是如何得到这些结论的。"
本作品保存的正是"如何得到结论"的全过程：结论只是副产品，思考轨迹才是交付物。

## 2. 一次推演的完整流程（固定五阶段，无循环）

```
提出问题（追问自动携带上一轮系统回答）
   │
   ▼
① 事实收口 ── 只把用户明确说出的事实列为"事实"；其余显式列为"缺失信息"，绝不替用户猜
   │
   ▼
② 模型匹配 ── 确定性检索（关键词/标签命中，可解释）→ LLM 从候选中选 2-4 个，
   │          必须含至少一对"张力模型"；不满足时由库内张力关系确定性兜底补入
   ▼
③ 独立推演 ── 每个模型各自给出结论（带五层标注）、成立条件、失效边界；先打架，不合谋
   │
   ▼
④ 交叉推演 ── 显式列出模型间冲突点 + "各自在什么条件下成立"；
   │          若无实质冲突，必须说明"一致成立的条件"与"什么证据出现后会分歧"；
   │          给出 1-3 个贝叶斯式证据检查点（什么新证据会改变判断）
   ▼
⑤ 综合结论 + 最小行动 ── 每句话带五层标注；数字默认"仅为示例，不是推荐阈值"；
      最小行动 + 事前写下的停止条件 + 观察窗口
   │
   ▼
存入认知账本（判断过程快照） → 复盘（实际结果回填） → 长期认知轨迹（复盘统计）
```

**防死循环的工程保证**：阶段数固定为 5；每个阶段最多调用模型 2 次（1 次正常 + 1 次 JSON 修复）；
任何一步失败即终止并返回明确错误，绝不伪造输出；推演不存在任何迭代循环。

## 3. 四个核心机制

### A. 真·张力交叉验证
检索模型时强制包含至少一对结论可能冲突的"张力模型"（如 沉没成本 × 路径依赖：
同样的"已投入"，一个说它是幻觉、一个说它是资产）。冲突点显式输出，并说明
"对比的目的不是选最正确的模型，而是判断不同模型分别在什么条件下成立"。

### B. 五层标注（区分每句话的成色）
| 标签 | 含义 | 颜色 |
| --- | --- | --- |
| 事实 | 用户已提供的信息 | 绿 |
| 推断 | 系统基于模型的推演 | 蓝 |
| 假设 | 尚未验证的假设 | 黄 |
| 缺失信息 | 目前缺失、需要补充的信息 | 红 |
| 示例数字 | 仅为说明方法的示例，不是推荐阈值 | 紫 |

模型 + AI 最容易制造"看起来非常理性和精确"的幻觉数字；五层标注让"认知形式感"
无法冒充"认知质量"。所有具体数字默认是"示例数字"，除非它来自用户提供的事实。

### C. 溯源回放
每一步为什么选这个模型（检索命中哪些关键词）、喂给模型的上下文是什么（含追问历史）、
模型的原始结构化输出是什么，全部留档。用户可以展开每一步，看见 AI 是怎么一步步得出答案的。

### D. 认知账本（保存判断过程，而非聊天记录）
一笔账本保存：当时的问题 → 已确认事实 → 关键假设 → 支持/反对证据（证据检查点）→
冲突与成立条件 → 决策理由 → 预期结果与观察窗口 → 停止条件。
复盘时回填"实际发生了什么"，标记哪些假设被推翻/确认，写下教训。
复盘统计页据此形成长期认知轨迹：**哪个假设常被现实推翻、哪种偏差反复出现**。

## 4. 逐条回应真实用户差评

| # | 差评要点 | 本作品的实现 |
| --- | --- | --- |
| 1 | 追问只喂用户输入，丢了上一轮回答 | 追问自动携带上一轮系统自己的回答摘要 + 全部历史（已用真实测试验证：追问判断点明确引用了上一轮上下文） |
| 2 | 多模型在"共同完成同一论证"，没有交叉推演 | 强制张力对（确定性兜底）；冲突点与各自成立条件显式输出；差评举例的"沉没成本 × 路径依赖 × 贝叶斯更新"正是默认示范问题的实际输出 |
| 3 | 8-12 周、30% 留存等数字无依据 | 无数据支撑的数字一律标注"仅为示例，不是推荐阈值"；事实收口阶段显式列出缺失信息（留存口径、CAC/LTV、行业基准等） |
| 4 | 需要区分事实/推断/假设/缺失信息/示例数字 | 五层标注贯穿所有输出（事实收口、每个模型的推演、综合结论） |
| 5 | 一万个模型无意义，关键是模型结构与认知操作类型 | 精选 30 个模型，每个标注认知操作角色（发现问题/生成解释/验证假设/判断概率/比较选择/检查偏差/分析动态）+ 谱系关系 |
| 6 | 只说"这是沉没成本"，不说要求执行什么动作 | 每个模型带 scaffoldAction（如沉没成本："把不可追回的投入先拿掉，只比较从今天起的未来收益"） |
| 7 | "保存思考结构"没落地，只是 Chat History + Learning Tracker | 认知账本保存判断过程（问题→事实→假设→证据→冲突→预测→停止条件→实际结果→推翻记录），复盘统计给出长期轨迹 |
| 8 | 帮助 AI 答得更好 vs 帮助人思考得更好 | 产品定位明确选择后者：一切界面围绕"看懂、记住、回顾 AI 怎么得出答案"设计 |
| 9 | 半年后回看"我当时为什么相信/哪个假设被推翻/常犯什么偏差" | 复盘统计页直接回答这三个问题（推翻率、常犯偏差信号、教训时间线） |

## 5. 诚实边界（拒绝幻觉的自我约束）

1. 模型库 30 个条目全部带真实信源（论文/书籍/百科），可点击查证；
2. 不伪造模型效果：推理层直接调用 DeepSeek API，未配置 Key 或调用失败时明确报错，不降级为假输出；
3. 检索是确定性关键词匹配（可解释、可复现），不引入不可解释的向量检索；
4. 账本与统计只基于用户自己提交的数据，不推断、不虚构；
5. 隐私说明：为实现推理，问题与上下文会发送给 DeepSeek API；除此之外不上传任何数据，
   账本默认存于本地文件（可切换华为云 RDS，见 lib/store.ts 适配器）。
